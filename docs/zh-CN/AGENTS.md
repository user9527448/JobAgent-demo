# JOBAGENT 仓库协作规范

> 英文原文：[AGENTS.md](../../AGENTS.md)。根目录英文文件是工具直接读取的规范；修改它时必须在同一提交中同步更新本中文镜像。

这些规范适用于整个仓库。

## 必需上下文

修改代码或项目配置前，阅读：

1. `docs/DEVELOPMENT_PLAN.md`
2. `docs/GITHUB_ISSUES.md`
3. `docs/WORKLOG.md`

除非用户明确调整优先级，否则按计划中的 Issue 顺序执行。

## 工作日志

在开发过程中持续更新 `docs/WORKLOG.md`：

- Issue 开始时添加记录。
- 记录重要实现决策和相对计划的偏离。
- 记录失败的检查、环境限制、阻塞项和需要用户执行的操作。
- Issue 完成时记录命令/检查及最终结果。
- 交还工作前更新当前状态和下一步。

不要把工作日志当作原始命令流水账。内容应简洁、客观，并能帮助后续恢复工作。

## 文档语言同步

- 项目文档必须维护为两个独立文件：一份英文版和一份简体中文版。
- 不得通过把既有英文文件改写成中文，或把既有中文文件改写成英文来满足翻译要求。必须保留每个文件原有语言并更新对应版本。
- 既有英文文档的中文镜像放在 `docs/zh-CN/`；既有中文文档的英文版本放在 `docs/en-US/`，除非仓库已经存在约定好的英文路径。
- 两种语言版本必须在同一提交中更新。新增文档时必须同时创建中英文版本，并在同一提交中加入相应索引。
- 遗留的单语文档最迟必须在下一次实质修改时补齐缺失版本；迁移完成前不得改变原文件的主要语言。
- 当前 `docs/WORKLOG.md` 中的混合语言历史属于遗留迁移项。以后不得继续在同一文件中切换语言来代替双份维护；拆分中英文日志时必须保留已有历史。
- 代码标识符、环境变量、错误码、URL 和命令不翻译。

## Git 工作流

- 不直接提交到 `main` 或 `develop`。
- 每个 Issue 创建一个 `feature/<issue>-<description>` 分支。
- 每个提交只包含当前 Issue 范围。
- 推送前运行格式、lint、类型检查和测试。
- 除非用户明确要求，否则不改写已发布历史，也不强制推送。

## Git 作者身份

- 新提交默认使用从用户本机现有全局 Git 配置复制到仓库级配置的作者身份，除非用户明确指定其他身份。
- 新提交不得使用 `Codex Agent` 或 `@local` 邮箱等占位身份。
- 环境或工作区发生变化后，提交前核对 `git config --local user.name` 和 `git config --local user.email`。
- 作者身份变更只适用于未来提交；不得仅为修改贡献者归属而改写已发布历史。
- GitHub 贡献者归属要求提交邮箱已关联并验证到用户的 GitHub 账号；不得把凭据或认证令牌提交进仓库。

## Python 环境

- 复用现有兼容 Python，不下载新 Python 版本，除非用户要求。
- 在仓库本地 `.venv` 中安装和使用项目依赖。
- `.venv`、密钥、运行时数据、日志和下载的来源文件不得进入 Git。

## 实现边界

- 采用满足当前 MVP Issue 的最简单架构。
- 不提前加入延期技术或功能。
- 保留原始招聘来源数据和可追溯性。
- 不绕过登录、CAPTCHA、访问控制或来源网站限制。
- 不提交真实凭据或个人数据。
