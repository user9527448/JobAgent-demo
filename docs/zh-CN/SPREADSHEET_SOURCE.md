## 2. 数据源边界

实现必须明确区分三层：

1. **原始观测层**：记录来源 URL/工作簿身份、工作表身份、获取时间、可获得的 provider 更新时间元数据、内容哈希及不可变原始快照引用。原始业务文件和下载快照属于运行数据，不得提交到 Git。
2. **清洗记录层**：执行确定性的表头、空白、日期和值规范化、分类、校验和去重。以有界安全原因码和来源坐标保留拒收行；绝不编造缺失值。
3. **统一岗位层**：把接受的行映射到现有稳定岗位查询边界并保留来源证据。Agent 和页面读取这一层，不直接读取任意工作簿单元格。

爬虫继续作为统一岗位的另一类生产者。JAI-052 不得删除爬虫数据表、Adapter、调度历史或来源证据。

## 3. 身份、刷新与幂等

准确身份规则必须在工作簿审计后审批。设计至少需要区分：

- 工作簿与工作表身份；
- 来源行身份或有文档说明的确定性回退身份；
- 行内容哈希与规范化内容哈希；
- 首次/最近观测时间及来源提供的更新时间（如有）；
- 未变化、已变化、新增、当前快照缺失及拒收观测。

重复刷新同一工作簿版本不得产生重复统一记录。后续快照中消失的行不得被自动硬删除；必须由获批策略决定标记为停用、过期或仅“本次未观测”。来源快照和导入运行必须可审计发现、接受、变化、未变化、拒收和缺失数量。

## 4. 清洗与分类

JAI-052 只能实现由实际工作簿证据确认并经审批的规则。候选分类可以包括单位、单位类型、地区、岗位族、学历、经验、报名截止时间、来源 URL 和自由文本备注，但审计确认前都不是既定来源列。

规则必须确定、可测试。歧义值保持显式，原始单元格文本可追溯，分类规则变化必须增加版本。合成固定样本可以模拟获批结构；真实工作簿行、个人数据、凭据和下载文件不得进入测试或 Git。

## 5. 访问与安全

- JAI-052 只从只读访问开始。
- 从 JOBAGENT 视角，该共享资源永久保持只读。任何实现、运维命令、测试或恢复路径均不得修改单元格、视图、筛选、排序、评论、共享、权限或其他来源状态；不存在写回模式。
- 公开链接只有在负责人提供并批准后才能登记为来源配置。私有链接、访问 Token、Cookie、密码和签名 URL 不得提交，也不得出现在日志、固定样本、数据库错误文本或文档中。
- 如果需要认证，必须在只读审计后另行审批访问机制和环境变量边界。不得绕过登录、验证码、访问控制、共享限制或 provider 条款。
- provider 错误映射为安全内部原因码；不持久化原始响应正文或密钥。

## 8. G1 接入检查清单

负责人提供链接后，在不暴露密钥的前提下登记：

- provider 和链接类型、公开或需认证访问；
- 工作簿身份、工作表清单、表头行、合并单元格、公式及隐藏行列；

## 9. G1 证据 — 2026-09-23

### 9.1 已观察事实

- 所提供资源是名为 `☛秋招+春招汇总表（全年直投）` 的公开共享飞书多维表格。准确共享 URL 及其查询参数只作为运行时信息，不登记到 Git。
- 匿名共享权限只允许查看和预览；不允许编辑、评论、导出、打印、协作管理、元数据管理、复制或查看操作历史。检查身份不是所有者。
- 主表 `❤秋招+春招汇总表` 报告 10,082 条记录，包含十个视图：秋招+春招汇总、实习汇总、往届可投汇总、免笔试汇总、央国企、外企、金融银行、互联网、艺术类及大专可投。
- 另可见三张表：200 条记录的 `央国企&事业单位`、321 条记录的 `内推码` 和 12 条记录的 `笔试题库`。没有检查其记录内容和完整字段 Schema；建议首期数据源不包含它们。
- 主表暴露 18 个字段：`投递链接`、`行业分类`、`工作地点`、`父记录 2`、`届次`、`批次`、`更新时间`、`学历要求`、`公司名称`、`公告链接`、`企业性质`、`文本 10`、`招聘岗位`、`是否笔试`、`公告来源`、`专业要求`、`截止时间` 和 `父记录`。
- 飞书 Schema 把 `更新时间` 标为主键，但时间戳不是稳定行身份。Provider 的表身份与记录 ID 可用，是更安全的来源身份。
- 启动响应只暴露了一个 2,000 条记录的值窗口，而元数据覆盖全部 10,082 条记录。该窗口中，公司、岗位、投递链接、公告来源和工作地点均为 2,000/2,000；富文本与多选字段存在对象、标量和数组混合表示，必须确定性规范化。
- 在该 2,000 条窗口中，投递链接有 35 个重复组、共 94 行，公告链接有 9 个重复组、共 18 行，而 `(公司名称, 招聘岗位, 投递链接)` 没有完全重复组。因此不能仅用 URL 作为来源行身份。
- 全部 10,082 条记录的修改元数据显示，按 `Asia/Shanghai`，2026-09-18 至 09-23 每日分别有 151、237、89、91、217、158 条修改。这证实来源仍在逐日变化，但不能证明仅追加，也不能保证未来刷新时刻。
- 检查只使用有界公开只读响应，并只在内存解码结构元数据。没有使用登录、凭据、写接口、导出、本地工作簿、原始行转储、数据库写入或 scheduler 操作。

### 9.2 未决问题

- 公开共享页面使用的浏览器端点不是已承诺的官方自动化契约，可能变化。周期性生产访问必须在 G4 单独审核稳定性、Provider 条款、速率限制和失败行为。
- 尚不清楚来源所有者是否愿意授权只读飞书 OpenAPI 应用。如果可获得此授权，正式 OpenAPI 是更耐久的连接方式；G2 不要求任何凭据。
- G1 未证明行删除、归档、重排、公式行为、隐藏字段及辅助表关系。因此缺失行只能登记为非破坏性观测，不得视为删除。
- `截止时间` 存在多种来源文本形式。只有无歧义日期可以进入统一截止日期；歧义/原始值必须保持可追溯并生成有界校验结果。

## 10. A-007/G2 建议

请求批准以下有边界的实现契约：

1. 首期只接入 `❤秋招+春招汇总表`；排除 `央国企&事业单位`、`内推码` 和 `笔试题库`。
2. 使用 `(provider, workbook/base identity, table_id, record_id)` 作为来源身份；规范化内容哈希只用于变化检测，绝不作为身份。
3. 复用现有 `sources`、`crawl_runs`、`raw_documents`、`job_posts` 和 `job_positions`；不建立第二套岗位域，也不删除爬虫证据。
4. 引入与 Provider 无关的只读 `SpreadsheetSnapshotReader` 边界。首个实现只使用合成固定样本和 `_test` 数据库，不执行真实周期获取。
5. 每次未来导入只获取一个有界快照并在内存规范化；绝不逐行请求 Provider。生产获取仍受 G4 保护。若来源所有者可授权只读应用，优先使用飞书正式 OpenAPI；否则任何临时公开共享 Adapter 都需要 G4 单独审批稳定性与条款。
6. 富文本规范为可见文本；标量/数组多选规范为有序去重列表；只接受 `http`/`https` URL 并移除跟踪参数；时间统一到 `Asia/Shanghai`；绝不编造缺失或歧义值。映射版本为 `feishu-rollup-v1`。
7. 公司映射到 `JobPost.organization`，规范化行业/企业性质保留为分类证据，地点映射到 `JobPost.region` 与岗位地点，投递链接映射到 `JobPost.apply_url`，无歧义截止日期映射到 `JobPost.deadline`，招聘岗位映射到 `JobPosition.name`，学历映射到 `JobPosition.education`，专业映射到 `JobPosition.major`。届次、批次、是否笔试、公告链接/来源、原始截止时间及其他未映射值先保留为可追溯原始证据，等待后续 Schema 决定。
8. 重复导入未变化记录必须复用现有版本；变化记录新增不可变原始文档版本及确定性统一投影。后续快照中缺失的记录在 G2 只记为 `not_observed` 证据，绝不硬删除或自动过期。
9. 将记录来源规范为只包含稳定表/记录身份的 `https` 来源 URL，并移除共享、用户和跟踪参数；准确共享链接只保存在 Git 之外的运行时配置中。
10. 所有测试只使用合成响应形状；需要 PostgreSQL 时，只使用名称以 `_test` 结尾的数据库。真实飞书行、共享 URL、Token、Cookie、个人数据或响应正文不得进入 Git、固定样本、日志或错误存储。

上述建议从未获批，只用于说明归档分支。路线已经撤回：不会实现 Reader/Parser、迁移、业务导入、周期请求、scheduler 变更、Agent/UI 或来源写回。项目继续按原关键路径推进。
